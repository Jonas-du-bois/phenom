## 2025-10-27 - [Nested Interactive Elements Accessibility]
**Learning:** When nesting interactive elements (like buttons) inside a clickable container (like a card with `@click` and `@keydown`), standard `click.stop` is insufficient for keyboard accessibility. The parent container's `@keydown.enter` listener will still catch the Enter key pressed on the child button unless `keydown.enter.stop` is also applied to the child. This causes duplicate actions or unexpected navigation.
**Action:** Always apply `@keydown.enter.stop` and `@keydown.space.stop` alongside `@click.stop` on interactive children within clickable parent containers.
## 2025-10-27 - [Focus Visible Styling for Custom Atomic Components]
**Learning:** Atomic custom UI components (`BaseButton`, `IconButton`, `BaseToggle`) that override native button styles require explicit `focus-visible` styling to ensure they are accessible via keyboard navigation. Without this, standard browser focus rings might not display correctly or contrast sufficiently.
**Action:** Always apply explicit Tailwind `focus-visible` classes (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[#00F0FF] focus-visible:ring-offset-2 focus-visible:ring-offset-transparent`) to custom atomic interactive components.
