## 2025-10-27 - [Nested Interactive Elements Accessibility]
**Learning:** When nesting interactive elements (like buttons) inside a clickable container (like a card with `@click` and `@keydown`), standard `click.stop` is insufficient for keyboard accessibility. The parent container's `@keydown.enter` listener will still catch the Enter key pressed on the child button unless `keydown.enter.stop` is also applied to the child. This causes duplicate actions or unexpected navigation.
**Action:** Always apply `@keydown.enter.stop` and `@keydown.space.stop` alongside `@click.stop` on interactive children within clickable parent containers.
## 2026-11-02 - [Focus-Visible for Interactive UI Components]
**Learning:** Relying on default browser focus states is often insufficient for custom UI components overriding native button/toggle styles. Using a programmatic focus in Playwright (`locator.focus()`) may not consistently trigger `:focus-visible` CSS pseudo-classes, requiring simulated natural keyboard navigation (e.g., `page.keyboard.press('Tab')`) to properly verify accessibility.
**Action:** Always implement explicit `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[#00F0FF] focus-visible:ring-offset-2 focus-visible:ring-offset-transparent` Tailwind utility classes for atomic custom components (BaseButton, IconButton, BaseToggle) to ensure highly visible and aesthetically pleasing keyboard navigation focus rings.
